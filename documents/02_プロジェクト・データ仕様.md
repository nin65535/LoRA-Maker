# プロジェクト・データ仕様

## 1. プロジェクトの単位

プログラム本体の配置場所とは別に、LoRA作成データを保存するプロジェクトフォルダを設ける。

プロジェクトフォルダは、LoRAの対象となる1キャラクターにつき1フォルダ作成する。1プロジェクトの中には、顔、衣装、全身等の複数の学習用データセットを定義できる。

各データセットは、工程間で変化しない`dataset.key`を分類キーとして持つ。識別タグはデータセットの属性であり、工程フォルダ名や分類キーには使用しない。

例：

| データセットキー | 用途 | 識別タグの例 |
| --- | --- | --- |
| `face` | 顔中心の画像 | `__tanshun_face__` |
| `outfit` | 衣装を含む画像 | `__tanshun_face__`, `__tanshun_outfit__` |
| `body` | 全身・体格中心の画像 | `__tanshun_face__`, `__tanshun_body__` |

## 2. 標準データフォルダ

| フォルダ | 役割 |
| --- | --- |
| `01_素材画像` | 動画生成等の入力となる素材画像を保存する |
| `02_動画` | ComfyUI等で生成した動画を保存する |
| `03_動画キャプチャ` | 動画から抽出した静止画を保存する |
| `04_拡大` | 選別後に拡大処理した完成画像を保存する |
| `05_タグ付け` | Taggerが生成した未加工のキャプションファイルを保存する |
| `06_LoRA学習素材` | kohya_ssが読み込む完成画像と加工済みキャプションを保存する |
| `07_LoRA` | 学習済みLoRA等の成果物を保存する |

フォルダ名、役割および表示順は全プロジェクトで共通とし、アプリ共通マスタで一元管理する。プロジェクト設定ファイルには重複して保存しない。

## 3. データセット別のサブフォルダ

`01_素材画像`から`05_タグ付け`までは、データセットキーをサブフォルダ名として使用する。

```text
01_素材画像/
├─ face/
├─ outfit/
└─ body/

02_動画/
├─ face/
├─ outfit/
└─ body/
```

識別タグは変更される可能性があるため、サブフォルダ名として使用しない。識別タグを変更しても、途中工程のフォルダ名やファイルの移動は発生させない。

`06_LoRA学習素材`では、kohya_ssの読込規則に合わせて次の形式へ変換する。

```text
<学習回数>_<データセットキー>/
```

例：

```text
06_LoRA学習素材/
├─ 20_face/
├─ 10_outfit/
└─ 10_body/
```

フォルダ名後半のデータセットキーは分類用であり、識別タグそのものではない。学習に使用する識別タグは各キャプションファイルへ書き込む。

## 4. 工程間のデータフロー

次の処理をデータセット単位で行う。

```text
01_素材画像/<dataset.key>
  ↓ 動画生成
02_動画/<dataset.key>
  ↓ フレーム抽出
03_動画キャプチャ/<dataset.key>
  ↓ 選別・拡大
04_拡大/<dataset.key>
  ↓ 完成画像をコピー
06_LoRA学習素材/<repeats>_<dataset.key>
  ↓ 画像を参照してタグ生成
05_タグ付け/<dataset.key>
  ↓ 原本タグをコピーしながら識別タグ追加・選択タグ削除
06_LoRA学習素材/<repeats>_<dataset.key>
  ↓ LoRA学習
07_LoRA
```

フォルダ番号は分類上の並びであり、厳密な実行順とは一致しない。

拡大結果の正本は`04_拡大`へ保存し、保存確認後に`06_LoRA学習素材`へコピーする。タグ付け工程は`06_LoRA学習素材`内の画像を参照し、未加工タグを`05_タグ付け`へ生成する。

## 5. 原本保持

すべての工程で作業元ファイルを必ず残す。

- 入力ファイルを直接変更しない
- 入力ファイルを移動、削除、上書きまたは名前変更しない
- 加工結果は対応する後工程のフォルダへ新規出力する
- 処理失敗時も入力側へ影響を与えない
- タグ編集でも`05_タグ付け`の未加工タグを変更しない
- `07_LoRA`の学習結果をmodelsフォルダへ配置する場合は移動ではなくコピーする

工程フォルダはフォルダ全体の完全な複製ではなく、その工程で生成または変更したファイルだけを保存する。タグ付けおよびタグ編集工程では画像を重複コピーしない。

## 6. タグファイルの保存

Taggerが生成した未加工のキャプションファイルは、対応する`05_タグ付け/<dataset.key>`へ原本として保存する。

タグ編集では原本を直接変更しない。未加工キャプションを読み込み、対象データセットに設定されたすべての識別タグの追加と、ユーザーが選択したタグの削除を行った結果を、対応する`06_LoRA学習素材/<repeats>_<dataset.key>`へ出力する。

例：`outfit`データセットに次の識別タグが設定されている場合、両方を全キャプションへ追加する。

```text
__tanshun_face__, __tanshun_outfit__
```

再編集時も加工済みタグへ変更を重ねず、常にTaggerの未加工出力から最終版を再生成する。

## 7. ファイルの対応付け

画像とキャプションは、同じデータセットおよび拡張子を除いた同じファイル名によって対応付ける。

途中工程では、原則としてデータセットキー、ファイル名および相対パスを維持する。サブフォルダを使用する場合も、後工程で対応関係を解決できるよう相対構造を引き継ぐ。

## 8. 生成動画の保存と命名

ComfyUIが生成した動画は、LoRA Maker専用の一時出力フォルダから、対応する`02_動画/<dataset.key>`へ移動して保存する。一時出力フォルダは完成データの保存先として扱わない。

保存ファイル名は次の形式とする。

```text
<プリセットキー>_<3桁連番>.<元の拡張子>
```

例：

```text
02_動画/outfit/camera_pan_001.mp4
02_動画/outfit/turnaround_001.mp4
02_動画/outfit/walk_001.mp4
02_動画/outfit/crouch_001.mp4
```

連番はデータセットかつプリセットキー単位とする。対応するデータセットフォルダ内にある同じプリセットキーの既存ファイルから最大番号を求め、その次の番号を採用する。欠番は再利用せず、既存ファイルを上書きしない。

## 9. 動画キャプチャの保存

キャプチャ画像は、データセットの下を動画名単位のフォルダに分けて保存する。

```text
03_動画キャプチャ/
└─ outfit/
   ├─ walk_001/
   │  ├─ frame_001.png
   │  └─ frame_002.png
   └─ crouch_001/
      └─ frame_001.png
```

一括キャプチャでは、キャプチャ画像が既に存在する動画を処理済みとしてスキップする。空フォルダだけが存在する場合は処理済みとみなさない。
