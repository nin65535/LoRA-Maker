# 設定ファイル仕様

## 1. 設定の分類

設定は次の3種類に分ける。

| 設定 | 保存対象 |
| --- | --- |
| プロジェクト設定 | キャラクター名、データセット、学習回数、複数の識別タグ、削除対象タグ等、1プロジェクト固有の情報 |
| アプリ共通マスタ | 工程フォルダの名称、役割、表示順、動画生成用共通ワークフローおよび動画生成プリセット等、全プロジェクト共通の情報 |
| アプリ個人設定 | 前回開いていたプロジェクト、ComfyUI接続先、Stability Matrix管理下のsd-scripts実行環境等、プロジェクトに属さない利用環境固有の情報 |

動画生成キュー、実行中ジョブおよび外部ツールとの一時的な作業状態は、プロジェクト設定とは分離してFastAPI側で管理する。

設定は論理的には「アプリ全体」と「プロジェクト」の2スコープに分ける。アプリ全体の設定は、配布物として管理するアプリ共通マスタと、利用PCごとに異なるアプリ個人設定の2ファイルへ物理的に分離する。

| ファイル | 標準保存先 |
| --- | --- |
| アプリ共通マスタ | アプリ配置場所の`app_master.json` |
| アプリ個人設定 | `%LOCALAPPDATA%/LoRAMaker/settings.json` |
| プロジェクト設定 | `<プロジェクトルート>/lora_maker.json` |

### 1.1 共通の保存形式

- JSON、UTF-8、LF改行、末尾改行ありとする
- JSONのキーは`camelCase`とする
- 各ファイルのルートに`application`と`schemaVersion`を持たせる
- 未設定値は空文字列ではなく`null`で表す
- 配列の順序は画面上の表示順として維持する
- 保存時は同一フォルダへ一時ファイルを作成し、検証後に原子的に置き換える
- 秘密情報、動画生成キュー、実行中ジョブ等の一時状態は保存しない

## 2. プロジェクト設定

各プロジェクトフォルダの直下に、プロジェクト固有設定を保存するJSONファイルを1個置く。

- 新規作成時のデフォルトファイル名は`lora_maker.json`とする
- 既存プロジェクトでは設定ファイル名を固定しない
- 設定ファイルの親フォルダをプロジェクトルートとみなす
- 工程フォルダ名、動画生成用共通ワークフローおよび動画生成プリセットの定義はプロジェクト設定へ保存しない

初期構造例：

```json
{
  "application": "lora-maker",
  "schemaVersion": 1,
  "project": {
    "key": "tanshun",
    "name": "たんしゅん"
  },
  "datasets": [
    {
      "key": "face",
      "name": "顔",
      "repeats": 20,
      "triggerTags": [
        "__tanshun_face__"
      ],
      "removedTags": []
    },
    {
      "key": "outfit",
      "name": "衣装",
      "repeats": 10,
      "triggerTags": [
        "__tanshun_face__",
        "__tanshun_outfit__"
      ],
      "removedTags": []
    },
    {
      "key": "body",
      "name": "全身",
      "repeats": 10,
      "triggerTags": [
        "__tanshun_face__",
        "__tanshun_body__"
      ],
      "removedTags": []
    }
  ]
}
```

`project.key`は表示名とは独立した変更しない識別子とし、英小文字、数字およびアンダースコアで構成する。デフォルトデータセットの識別タグテンプレートにある`${project}`の置換値として使用する。`project.name`を変更しても、生成済みの識別タグは変更しない。

## 3. データセット設定

1プロジェクトには複数のデータセットを登録できる。各データセットは次の属性を持つ。

| 項目 | 内容 |
| --- | --- |
| `key` | 工程間の分類とフォルダ対応に使用する変更しない識別子 |
| `name` | 画面表示用の名称 |
| `repeats` | kohya_ss用フォルダ名へ使用する学習回数 |
| `triggerTags` | 当該データセットの全キャプションへ追加する識別タグ配列 |
| `removedTags` | 当該データセットで削除対象として選択されたタグ配列 |

### 3.1 データセットキー

- 英小文字、数字およびアンダースコアで構成する
- プロジェクト内で重複させない
- `01_素材画像`から`05_タグ付け`までのサブフォルダ名として使用する
- 作成後の変更は原則として行わない
- 表示名や識別タグを変更してもデータセットキーは変更しない

### 3.2 識別タグ

- 1データセットに複数設定できる
- 設定された識別タグは、当該データセットの全キャプションへ追加する
- 例として衣装データセットには、顔と衣装の両方の識別タグを設定できる
- 識別タグは属性データとして扱い、工程フォルダの分類には使用しない
- タグ編集画面の削除対象選択では、設定済み識別タグを削除できないようにする

同一データセット内で一部の画像だけ識別タグ構成が異なる運用は初期実装の対象外とする。その場合は別データセットに分割する。

### 3.3 学習回数

- 1以上の整数とする
- `06_LoRA学習素材/<repeats>_<dataset.key>`のフォルダ名へ反映する
- 学習素材配置後に変更した場合は、既存フォルダとの不一致を画面へ警告する

## 4. アプリ共通マスタ

工程フォルダの名称、役割および表示順、新規プロジェクト用のデフォルトデータセット、動画生成用共通ワークフローおよび動画生成プリセットは、`app_master.json`で一元管理する。

```json

    { "key": "trainingDataset", "name": "06_LoRA学習素材" },

  ],
  "defaultDatasets": [
    {
      "key": "face",

      "repeats": 20,

      "key": "outfit",
```

### 4.1 デフォルトデータセット

`defaultDatasets`は新規プロジェクト作成時の雛形とする。作成時に内容をディープコピーしてプロジェクト設定の`datasets`へ保存し、以降のアプリ共通マスタ変更を既存プロジェクトへ自動反映しない。

`triggerTags`では次のプレースホルダを使用できる。

| プレースホルダ | 置換値 |
| --- | --- |
| `${project}` | 新規プロジェクトの`project.key` |
| `${dataset}` | 対象デフォルトデータセットの`key` |

プレースホルダは新規プロジェクト作成時に一度だけ置換し、プロジェクト設定には置換後の文字列を保存する。たとえば`project.key`が`tanshun`、データセットキーが`outfit`の場合、`__${project}_${dataset}__`は`__tanshun_outfit__`となる。

### 4.2 動画生成用共通ワークフロー

動画生成用ComfyUIワークフローは、アプリ全体で共通の1個を管理する。プリセットごとにワークフローJSONを複製しない。

共通ワークフローの定義には、少なくとも次の情報を持たせる。

- ワークフローJSONの参照先
- 差し替え対象となる画像入力ノードを識別する情報
- 差し替え対象となるポジティブプロンプト入力ノードを識別する情報
- 差し替え対象となるネガティブプロンプト入力ノードを識別する情報
- 回収対象となる出力ノードを識別する情報

ノードID等はワークフロー変更によって変わる可能性があるため、処理コードへ固定値として埋め込まず、アプリ共通マスタで管理する。

### 4.3 動画生成プリセット

共通ワークフローへ適用するポジティブプロンプトとネガティブプロンプトは、動画生成プリセットとして`app_master.json`の`movieGeneration.presets`で管理する。この配列を動画生成時の選択肢の正本とし、件数やキーを処理コードおよび画面へ固定しない。追加・削除はアプリ再起動時に読み込まれ、選択肢、入力検証および出力ファイル名へ反映される。

各プリセットには、ファイル名へ使用できる識別キー、表示名、`positivePrompt`および`negativePrompt`を持たせる。プリセットキーは英小文字、数字およびアンダースコアで構成し、プリセット間で重複させない。

将来、動作ごとにプロンプト以外の設定差が必要になった場合は、プリセットへ対象ノードの入力値上書きを追加できる構造を検討する。ただし初期実装ではポジティブプロンプトとネガティブプロンプトの差し替えだけを対象とする。

実行時は共通ワークフローをメモリ上で複製し、入力画像と選択プリセットの両プロンプトを差し替える。保存されている元のワークフローJSONは変更しない。

各`nodeId`の具体値はComfyUI連携方式とAPI用ワークフローを検証した後に確定する。

## 5. アプリ個人設定

前回開いていたプロジェクト設定ファイルのパスなど、プロジェクトに属さない情報を保存する。環境依存の絶対パスや接続先はアプリ共通マスタへ入れず、アプリ個人設定で管理する。

少なくとも次の項目を持たせる。

- 前回開いていたプロジェクト設定ファイルのパス
- ComfyUI APIのベースURL
- LoRA Maker専用のComfyUI動画出力フォルダ
- Stability Matrix管理下でsd-scriptsを実行するPython実行ファイルのパス
- sd-scriptsの配置先または学習スクリプトのパス
- sd-scripts実行時の作業ディレクトリ
- 学習成果物の一時出力先または出力先指定方法

sd-scriptsの学習設定TOMLは環境依存の絶対パスとして保存しない。アプリ配置場所の`external_configs/training_configs/`直下に置き、画面では同フォルダ内の`.toml`ファイルを選択する。初期版ではサブフォルダを走査せず、任意パス入力も受け付けない。

Stability Matrixや各パッケージの再インストール・更新で実体パスが変わる可能性があるため、起動時および各処理の開始前に必要なパスを検証する。Python環境やsd-scriptsのパスをコードへ決め打ちしない。

初期構造は次のとおりとする。

```json
{
  "application": "lora-maker",
  "schemaVersion": 1,
  "lastProjectConfigPath": null,
  "comfyui": {
    "apiUrl": "http://127.0.0.1:8188",
    "movieOutputPath": null
  },
  "sdScripts": {
    "pythonPath": null,
    "rootPath": null,
    "workingDirectory": null,
    "trainingOutputPath": null
  }
}
```

アプリ起動時は、アプリ個人設定に記録された前回のプロジェクトを自動的に開く。

## 6. ネイティブ選択ダイアログによるプロジェクト切替

画面の「プロジェクトを開く」操作により、FastAPIを実行しているPythonプロセスからWindowsのネイティブファイル選択ダイアログを表示する。選択したプロジェクト設定JSONの絶対パスをPython側で取得し、現在のプロジェクトを切り替える。

ブラウザへドロップされたファイルやブラウザ標準のファイル入力からはローカルの絶対パスを取得できないため、ドラッグ＆ドロップによる切替は採用しない。

### 6.1 検証条件

- 選択するファイル名は任意とする
- JSONとして解析できることを確認する
- アプリ識別値を確認する
- 対応可能なスキーマバージョンを確認する
- 必須項目および設定値を検証する
- データセットキー、学習回数および識別タグ配列を検証する

### 6.2 切替時の安全性

- すべての検証に成功した場合だけプロジェクトを切り替える
- 検証中に現在のプロジェクトを閉じない
- 読み込みと検証が完了した後に一括して切り替える
- 不適格なJSONの場合は現在のプロジェクトを維持する
- 不適格だった理由を画面へ表示する
- 読み込み失敗時および選択をキャンセルした場合は、前回プロジェクトの記録も変更しない
- 待機中または実行中のジョブがある場合は、プロジェクトの新規作成、読込および切替を禁止する
