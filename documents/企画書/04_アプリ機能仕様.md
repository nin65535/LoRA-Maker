# アプリ機能仕様

## 1. アプリの役割

LoRA Makerは、Stability Matrix、ComfyUI、BandiViewおよびsd-scripts等を置き換えず、既存ツールを束ねる工程管理ランチャーとする。

主な役割は次のとおりとする。

- プロジェクトの作成、選択および切替
- 各工程の状態、対象フォルダおよびファイル数の表示
- 複数データセットと識別タグの管理
- 素材画像と動画生成プリセットを選択した動画生成
- BandiViewで対象フォルダを開く
- 動画からのフレーム抽出
- 選別画像の拡大と学習素材への配置
- タグ集計およびタグ一括編集
- Stability Matrix管理下の環境からsd-scriptsによる学習開始
- 学習済みLoRAのmodelsフォルダへの配置と削除
- 必要に応じた処理ログの表示
- 中断後の工程再開支援

既存ツールで十分使いやすい機能は再実装しない。特に動画および画像の人力選別には既存ツールを利用し、専用選別UIを実装しない。

## 2. UI共通仕様

### 2.1 基本構成

- React/TypeScriptによるSingle Page Applicationとする
- ヘッダーにアプリ名と現在のキャラクター名を表示する
- アプリ名は進捗確認用トップページへのリンクとする
- トップページと7工程をタブナビゲーションで切り替える
- タブを移動しても、FastAPI側で開始済みの処理は継続する
- ブラウザ再読込後も実行中または完了済みの処理状態を再取得できるようにする
- 共通領域にComfyUI APIの接続状態と、LoRA Makerが開始したsd-scripts学習プロセスの状態を表示する

ComfyUIおよびkohya_ss / sd-scriptsの導入と更新はStability Matrixへ委譲する。LoRA Makerは初期版ではStability Matrixの画面操作、パッケージの起動・停止および更新を自動化しない。ComfyUIが必要な工程で停止している場合は、利用者へStability Matrixからの起動を案内する。

タブは次の順序とする。

1. トップ
2. `01_素材画像`
3. `02_動画`
4. `03_動画キャプチャ`
5. `04_拡大`
6. `05_タグ付け`
7. `06_LoRA学習素材`
8. `07_LoRA`

### 2.2 画面幅

- 幅1920pxの全画面表示を基本とする
- デスクトップ画面の縦2分割表示も想定する
- 一覧情報が多いタブでは、狭い表示幅で表の横スクロールまたはカード状レイアウトへ切り替える
- タブ名を判別できない幅まで均等縮小せず、必要に応じてタブ領域を横スクロールさせる

### 2.3 共通の処理状態

時間のかかる処理は、最低限次の状態を画面上で識別できるようにする。

- 待機中
- 実行中
- 完了
- 失敗
- キャンセル

失敗時は、再実行の判断に必要なエラー内容または外部ツール側の応答を表示する。

## 3. プロジェクト管理

- 1キャラクターにつき1プロジェクトを管理する
- 1プロジェクト内に複数の学習用データセットを登録できる
- 新規プロジェクト作成時に標準データフォルダとプロジェクト設定JSONを作成する
- データセット追加時に`01_素材画像`から`05_タグ付け`までの対応サブフォルダを作成する
- アプリ起動時に前回開いていたプロジェクトを開く
- Windowsのネイティブファイル選択ダイアログでプロジェクト設定JSONを選択して切り替える

フォルダ構成は[02_プロジェクト・データ仕様.md](02_プロジェクト・データ仕様.md)、設定の検証条件は[03_設定ファイル仕様.md](03_設定ファイル仕様.md)を参照する。

## 4. トップタブ

各工程フォルダ内のファイル数を集計し、プロジェクト全体の大まかな進捗を表示する。

| 工程 | 主な表示内容 |
| --- | --- |
| 素材画像 | データセット数、画像数 |
| 動画 | 完成動画数、待機中・実行中・失敗ジョブ数 |
| 動画キャプチャ | 動画数、抽出済み動画数、画像総数 |
| 拡大 | 対象フォルダ数、拡大済み画像数 |
| タグ付け | 未加工キャプション数、編集済みキャプション数 |
| LoRA学習素材 | 画像・キャプションの正常ペア数、不足ファイル数 |
| LoRA | 学習結果数、modelsフォルダへの配置状態 |

単純な総ファイル数だけでなく、処理失敗、画像とキャプションの不一致等、次工程を妨げる状態も表示する。

## 5. `01_素材画像`タブ

データセットの定義と素材画像数を一覧表示する。

各データセットについて、少なくとも次を表示または編集できるようにする。

- データセットキー
- 表示名
- 学習回数
- 複数の識別タグ
- 素材画像数
- 対象フォルダを開く操作

識別タグと学習回数は素材画像を用意する時点で設定する。識別タグは1データセットに複数登録できる。例えば`outfit`には`__tanshun_face__`と`__tanshun_outfit__`を設定できる。

入力値の検証条件は[03_設定ファイル仕様.md](03_設定ファイル仕様.md)を参照する。

## 6. `02_動画`タブ

### 6.1 画面構成

次の三つの領域を表示する。

1. 素材画像と動画生成プリセットの一覧
2. 動画作成予定キュー
3. 作成済み動画一覧

素材画像には所属データセットを表示する。動画生成プリセットは、カメラパン、その場で一回転、歩く、しゃがむの4種類とする。動画生成用ComfyUIワークフロー自体はアプリ全体で共通の1個とし、画面上でワークフローを選択させない。任意のワークフローを自動解析せず、共通ワークフロー設定に差し替え対象ノードと回収対象出力を明示する。

### 6.2 キュー

- 素材画像とプリセットの組み合わせをキューへ追加できる
- キュー追加後に別の承認操作は要求しない
- 実行中ジョブがなければ即時に動画生成を開始する
- 実行中ジョブがある場合は待機状態とし、先行ジョブ完了後に自動開始する
- ComfyUIの専用出力フォルダを共有するため、同時実行数は1とする
- 実行中でも新しい要求を待機キューへ追加できる
- 失敗ジョブには再実行操作を設ける

キューと実行状態はReactのメモリだけに保持せず、FastAPI側で管理する。

### 6.3 動画生成処理

動画生成は次の順序で実行する。

1. 設定された出力先がLoRA Maker専用のComfyUI動画出力フォルダであることを検証する
2. 実行前に同フォルダ配下のファイルをすべて削除する
3. 共通ワークフローをメモリ上で複製する
4. 画像入力を選択画像へ、プロンプト入力を選択プリセットの内容へ差し替える
5. ComfyUIへ送信し、動画1本を生成する
6. 生成された動画を`プリセットキー_3桁連番`へリネームする
7. 素材画像と同じデータセットの`02_動画/<dataset.key>`へ移動する
8. 移動先に動画が保存されたことを確認する
9. 実行後にComfyUI動画出力フォルダ配下のファイルをすべて削除する

保存されている元のワークフローJSONは変更しない。動画の拡張子はComfyUIが生成した元の拡張子を維持する。採番規則は[02_プロジェクト・データ仕様.md](02_プロジェクト・データ仕様.md)を参照する。

### 6.4 出力フォルダ削除の安全性

- 削除対象はアプリ共通設定で明示されたLoRA Maker専用のComfyUI動画出力フォルダに限定する
- ComfyUI全体の出力フォルダを他用途と共有しない
- 設定値が空、存在しない、ファイルシステムのルート、ComfyUIのルートまたはプロジェクトルートを指す場合は削除を実行しない
- 移動先ファイルの保存確認前に、生成動画を削除しない
- 削除または移動に失敗した場合は処理を失敗として表示する

### 6.5 対象外

本機能は動画1本の生成までを担当し、次は対象外とする。

- 動画のプレビューによる品質評価
- リテイク要否の判断および自動再生成
- 採用動画の選別
- 動画内の破綻箇所の検出
- ComfyUIへ生成済み動画を読み込み、条件を変更して派生版を作る操作
- 4種類の動画を1操作で一括登録する機能

特に「その場で一回転」は入力画像にない背面を補完するため、リテイクが多くなるが、その判断と再生成操作はComfyUI上で行う。

## 7. `03_動画キャプチャ`タブ

データセット、動画およびキャプチャ済み画像枚数の対応表を表示する。

各動画に個別実行ボタンを設け、画面全体には一括実行ボタンを設ける。

- 一括実行ではキャプチャ画像が既に存在する動画をスキップする
- 空フォルダだけが存在する場合は処理済みとみなさない
- 再実行はユーザーの明示操作とする
- キャプチャ画像は`03_動画キャプチャ/<dataset.key>/<動画名>/`へ保存する
- 処理中の動画、完了、失敗を一覧上で識別できるようにする

## 8. `04_拡大`タブ

キャプチャ画像の入ったフォルダを一覧表示する。

各行に次を表示する。

- データセット
- キャプチャフォルダ名
- キャプチャ画像枚数
- 拡大済み画像枚数
- 選別ボタン
- 拡大ボタン

### 8.1 選別

選別ボタンを押すと、BandiViewを該当キャプチャフォルダを対象として起動する。

BandiViewの画像保存フォルダを複数の選別対象で共用する場合は、選別画像の混在を防ぐため、アプリ側で選別中の対象を1個だけ管理する。未処理の選別画像が残っている間は別対象の選別開始を禁止するか、警告する。

### 8.2 拡大

拡大ボタンを押すと、BandiViewの画像保存フォルダ内の画像を現在の対象に対する選別済み画像として扱い、次の順序で処理する。

1. 保存フォルダ内に対象画像が存在することを確認する
2. ComfyUIを利用して画像を拡大する
3. 拡大結果の正本を`04_拡大/<dataset.key>`へ保存する
4. 保存を確認する
5. 同じ画像を`06_LoRA学習素材/<repeats>_<dataset.key>`へコピーする
6. すべての処理成功後にBandiViewの画像保存フォルダを空にする

途中で失敗した場合は、原因調査と再実行ができるようBandiViewの画像保存フォルダを自動削除しない。

## 9. `05_タグ付け`タブ

### 9.1 画面構成

データセット単位で次を表示する。

- データセット名
- 設定済み識別タグ
- 対象画像数
- 未加工キャプション数
- 加工済みキャプション数
- タグごとの出現回数と出現率
- タグ付けボタン
- 配置ボタン

### 9.2 タグ付け

タグ付けボタンを押すと、対応する`06_LoRA学習素材/<repeats>_<dataset.key>`内の全画像を対象にTaggerを実行する。生成された未加工キャプションは`05_タグ付け/<dataset.key>`へ保存する。

### 9.3 削除予定タグの選択

- タグ名をクリックするとグレーアウトし、削除予定状態にする
- もう一度クリックすると削除予定状態を解除する
- クリックした時点ではキャプションファイルを変更しない
- データセットに設定された識別タグは別枠で固定表示し、削除予定にできないようにする
- 削除予定タグはデータセット単位でプロジェクト設定へ保存する

表示例：

```text
タグ                         出現数
1girl                        64 / 64
solo                         64 / 64
black_dress                  61 / 64
red_eyes                     57 / 64
long_hair                    55 / 64
standing                     22 / 64
looking_at_viewer            31 / 64
smile                        18 / 64
```

### 9.4 配置

配置ボタンを押すと、次の処理を行う。

1. `05_タグ付け/<dataset.key>`の未加工キャプションを読み込む
2. データセットに設定されたすべての識別タグを各キャプションへ追加する
3. ユーザーが削除予定として選択したタグを削除する
4. 加工結果を`06_LoRA学習素材/<repeats>_<dataset.key>`へ出力する

再実行時も加工済みキャプションへ変更を重ねず、常に未加工キャプションから最終版を再生成する。

## 10. `06_LoRA学習素材`タブ

このタブは確認を目的とし、学習素材に対する編集操作は設けない。

データセット単位で次を表示する。

- kohya_ss用フォルダ名
- 学習回数
- 設定済み識別タグ
- 画像数
- キャプション数
- 正常な画像・キャプションのペア数
- 画像だけ存在する件数
- キャプションだけ存在する件数
- 対象フォルダを開く操作

画像とキャプションに不一致がある場合は、`07_LoRA`の学習開始前に警告する。

## 11. `07_LoRA`タブ

次の操作と情報を提供する。

- 学習開始ボタン
- 学習状態とログ
- `07_LoRA`内の学習結果ファイル一覧
- LoRAをmodelsフォルダへ配置するボタン
- LoRAをmodelsフォルダから削除するボタン

学習開始前に、`06_LoRA学習素材`の画像とキャプションの対応および対象データセットの存在を検証する。

学習は、Stability Matrixがkohya_ss用に構築したPython環境からsd-scriptsを直接CLI実行する方式を第一候補とする。実行方法は事前検証で確定し、kohya_ss GUIの画面自動操作は行わない。学習中はComfyUIによる生成処理を開始せず、ComfyUI側の生成処理中にも学習を開始しない。

modelsフォルダへの配置は移動ではなくコピーとし、`07_LoRA`の学習結果を原本として残す。modelsフォルダからの削除も配置先コピーだけを対象とし、`07_LoRA`の原本を削除しない。

同名ファイルが存在する場合は、少なくとも次の状態を区別する。

- 未配置
- 配置済み・同一
- 配置済み・内容不一致

内容不一致のファイルを上書きまたは削除する場合は、対象を明示して確認する。
