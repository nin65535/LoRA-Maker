# ロードマップ完了後の運用改善記録

## 1. 位置付け

フェーズ0〜10の完了後、実運用を想定した確認で判明した操作性、データ保全および工程間連携の課題を改善した。

本記録は変更理由と旧仕様からの差分を残すものであり、現行仕様の正本ではない。現在の動作は`documents/企画書`の各仕様書を参照する。フェーズ0〜10の完了状態は維持する。

## 2. 変更の目的

- 工程ごとに分散していた個人設定を一か所で安全に編集できるようにする
- 選別した原寸画像を保持し、等倍と2倍の学習素材を独立して作成できるようにする
- プロジェクト設定の編集、データセット削除および工程生成物の削除で、意図しないデータ変更を防ぐ
- 動画とLoRA成果物の名前から入力元と実行単位を識別できるようにする
- ジョブ完了後の画面更新や一括操作を増やし、日常運用の手作業を減らす

## 3. 主な仕様変更

### 3.1 プロジェクトと設定の編集

- 新規プロジェクトでは保存ダイアログから任意のJSONファイル名を指定できるようにした
- キャラクター表示名を任意入力とし、空の場合は`project.key`を画面上の識別に使用するようにした
- 現在のプロジェクトを閉じて未選択状態へ戻せるようにした
- 素材画像タブと設定タブは、表示時に保存済み設定を読み直して編集コピーを作り、明示的な保存までは有効設定やファイルへ反映しない方式へ変更した
- 未保存状態でのタブ移動、ブラウザ再読込および終了時に破棄警告を表示するようにした
- ComfyUI、BandiView、sd-scriptsおよびmodels配置先等の個人設定を独立した設定タブへ集約した
- 待機中または実行中のジョブがある間は、プロジェクトや個人設定を変更できないようにした

### 3.2 データセットと工程生成物の保護

- データセット削除は、`01_素材画像`から`06_LoRA学習素材`まで対象データセットに関連するファイルがない場合だけ許可するようにした
- 学習回数の変更時は`06_LoRA学習素材/<repeats>_<dataset.key>`を追従してリネームし、変更前後の両方にデータがある場合は保存を中止するようにした
- トップ画面から工程別に生成物をクリアできるようにし、確認、実行中ジョブの検査、対象パスの制限および必要な空フォルダの再作成を行うようにした
- `01_素材画像`、プロジェクト設定JSONおよびプロジェクト外のmodels配置済みファイルは工程クリアの対象外とした
- `06_LoRA学習素材`のクリア時は、対応する倍率別処理履歴も消去するようにした
- 完了、失敗およびキャンセル済みのジョブ履歴だけを削除できるようにした

### 3.3 選別・拡大工程

- 工程名を`04_拡大`から`04_選別・拡大`へ変更した
- BandiView終了時に、共用保存フォルダの選別画像を`04_選別・拡大/<dataset.key>/<キャプチャフォルダ>`へ移動するようにした
- `04_選別・拡大`を選別済み原寸画像の保管場所とし、拡大結果の正本は置かない方式へ変更した
- 原寸のまま配置する`拡大×1`と、ComfyUIで4倍化後に50%縮小する`拡大×2`を追加した
- 同じ原寸画像でも倍率が異なれば別素材として配置でき、同一画像かつ同一倍率の再配置だけを重複として停止するようにした
- 配置先は`06_LoRA学習素材/<repeats>_<dataset.key>`とし、処理後も選別済み原寸画像を保持するようにした
- 学習素材の追加成功後、今回追加した画像を対象とするタグ付けジョブを自動登録するようにした

### 3.4 動画、フレームおよび学習成果物

- 生成動画名を`<プリセットキー>_<連番>`から`<素材ファイル名>_<プリセットキー>_<3桁連番>.mp4`へ変更した
- ComfyUIへ送る動画ワークフローの保存ノードへ、LoRA Maker専用一時出力先の`filename_prefix`を設定するようにした
- 専用一時出力フォルダが存在しない場合は安全検証後に作成し、mp4以外の生成物は拡張子だけを変更せず失敗として扱うようにした
- 全データセットを対象にした未処理動画の一括フレーム抽出と、抽出先をExplorerで開く操作を追加した
- 動画生成またはフレーム抽出の完了通知後、対象一覧と工程集計を自動更新するようにした
- LoRA成果物名を`<学習登録日のYYMMDD>_<project.key>_<3桁連番>`として自動採番するようにした

## 4. 既存データへの影響

- 既存の`04_拡大`フォルダは自動的に`04_選別・拡大`へ移行しない。アプリ共通マスタとプロジェクトの実フォルダ名が一致している必要がある
- 旧方式で`04_拡大`へ保存した拡大済み画像は、新方式が期待する「キャプチャフォルダ別の選別済み原寸画像」とは意味が異なるため、そのまま入力として扱わない
- 既存の`06_LoRA学習素材`は保持される。新しい倍率別履歴がない既存画像については、配置時に内容の完全一致検査で重複を防ぐ
- 旧命名の動画とLoRA成果物は削除または改名しない。新規生成分から新しい命名規則を適用する
- プロジェクト設定JSONのファイル名は引き続き固定しないため、既存の`lora_maker.json`もそのまま利用できる

## 5. 移行時の注意

1. アプリ共通マスタの工程フォルダ名が`04_選別・拡大`になっていることを確認する
2. 既存の`04_拡大`にデータがある場合は、原寸画像と拡大済み画像を区別し、自動移動せず内容を確認して移行する
3. BandiViewの共用保存フォルダに未処理画像がない状態で新方式の選別を開始する
4. 個人設定を設定タブで確認し、ComfyUI、BandiView、sd-scriptsおよびmodels配置先を保存する
5. 既存プロジェクトを開き、工程サマリーの警告、学習素材の画像・キャプション対応および既存成果物の配置状態を確認する
6. 工程クリアは生成物を削除する操作であるため、対象工程とバックアップを確認してから実行する
